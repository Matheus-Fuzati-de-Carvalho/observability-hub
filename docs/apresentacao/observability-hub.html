O problema

Três gargalos que toda consultoria de dados enfrenta

Discovery

Lento

Mapear o que existe — datasets, tabelas, volumes, donos — consome dias de trabalho manual via console GCP ou queries avulsas.

Monitoria

Reativa

SLA de recebimento de bases é acompanhado manualmente ou não é acompanhado — falhas só aparecem quando alguém nota a ausência dos dados.

Qualidade

Cara de medir

Perfilar colunas e tabelas exige escrever queries específicas a cada novo projeto, repetindo esforço que nunca vira ativo reutilizável.

O Hub resolve os três numa única interface, direto sobre BigQuery e Cloud Storage — sem mover dados, sem pipeline adicional.

Como escala

Um Hub, qualquer projeto GCP

ADR-006 — a service account de runtime do Hub recebe leitura nos projetos alvo; o usuário informa qual projeto quer inspecionar, sem precisar instalar nada lá.

Admin do projeto alvoconcede as roles à SA, uma vez
→
Usuário no Hubinforma o project_id
→
Todos os módulospassam a operar sobre ele

Sem OAuth, sem troca de token — simples de implementar, pensado para o cenário real de consultoria.

Checklist vivo por projeto alvo
  • APIs habilitadas (BigQuery, Storage, Logging)
  • Roles IAM concedidas à SA de runtime do Hub
  • Data Access audit logs configurados
  • Registrado em docs/onboarding-cliente.md antes de fechar a tarefa
Tração

Este piloto já foi importado para o repositório real da empresa e aponta para o projeto GCP de produção da dp6 — não é mais só prova de conceito.
